# مسار الإصدارات اليدوية — نوادر العملات

تم اعتماد هذا المسار لتسريع الإنجاز ومنع تداخل التعديلات.

## الفروع المعتمدة
- `specialist/maintenance` — أخصائي الصيانة: إصلاح الأعطال والمشكلات التشغيلية فقط.
- `specialist/cleanup` — أخصائي التنظيف: إزالة التكرار والفوضى والملفات غير اللازمة دون المساس بالبيانات أو الوظائف المعتمدة.
- `specialist/development` — أخصائي التطوير: إضافة وتحسين المزايا والواجهات الجديدة.
- `manager/manual-releases` — المدير: مراجعة مخرجات الاختصاصيين، حل التعارضات، وتجهيز إصدار يدوي نهائي.
- `main` — النسخة المستقرة؛ لا يتم تعديلها ضمن العمل اليومي.

## قاعدة العمل
1. كل اختصاصي يعمل في فرعه فقط.
2. لا يدمج أي اختصاصي مباشرة إلى `main`.
3. كل دفعة عمل تُسلَّم للمدير مع: رقم إصدار مقترح، الملفات المعدلة، ملخص التغييرات، وخطوات الاختبار.
4. المدير يجمع التعديلات المتوافقة في `manager/manual-releases` ويجري مراجعة نهائية.
5. بعد الاعتماد يُجهَّز إصدار مرقّم مثل `V5.6.3` أو `V5.6.4` للتثبيت اليدوي.
6. التثبيت على النسخة التشغيلية يتم يدويًا فقط بعد اعتماد المدير والمستخدم.
7. عند ظهور خلل، يتم الرجوع مباشرة إلى الإصدار السابق المعتمد.

## الأولويات الحالية
- الصيانة: الحفظ، الكمية، الصور، ظهور المقتنى في السوق، ومنع أخطاء «نفذت الكمية».
- التنظيف: إزالة التكرار والحشو والملفات/الواجهات القديمة دون حذف بيانات حقيقية.
- التطوير: تبسيط نموذج إضافة المقتنى والسوق وتحسين تجربة الإدارة والبائع.
- البث المباشر والمزايدة: مجمّدان مؤقتًا كمرحلة مستقلة حتى استقرار الأساسيات.

## صيغة تسليم كل إصدار
- رقم الإصدار
- الاختصاص المسؤول
- الهدف
- الملفات التي تغيرت
- ما تم إصلاحه/إضافته
- ما لم يتم المساس به
- نتيجة الاختبار
- طريقة الرجوع للإصدار السابق
