## خط الأساس المستقر

- نقطة الرجوع المستقرة المعتمدة: `9e555ec203370d2f92ea6f6ceb067444b36dc47c`
- القاعدة: لا تعديل مباشر على `main` قبل اختبار منفصل.

## النتائج الأولية
1. يوجد عدد كبير من ملفات ترقيات تاريخية وملفات تعليمات قديمة في جذر المشروع.
2. يوجد عدد كبير من GitHub Actions من نوع `apply-*`، كثير منها صُمم لترقيات موضعية سابقة. تعدد هذه الملفات يزيد احتمال إعادة تشغيل تعديل قديم عند تغيير ملف مرتبط به.
3. توجد ملفات بأسماء متقاربة أو مكررة، وبعضها يحمل نفس المحتوى/نفس SHA بأسماء مختلفة، وهو مؤشر واضح على تكرارات يجب تنظيفها بعد إثبات عدم استخدامها.
4. توجد ملفات تشغيل/إدارة قديمة ومساعدة يجب تصنيفها قبل الحذف إلى: مستخدم فعليًا / مرجع فقط / مكرر / مهجور.
5. لا يجوز إزالة أي ملف بيانات أو مصادقة أو إعدادات تشغيلية ضمن تنظيف الواجهة بدون مراجعة منفصلة.

## نقاط الدخول المعتمدة قبل أي تنظيف
- الخادم الرئيسي: `server.py`
- الإدارة: `admin/index.html`
- منطق الإدارة: `admin/app.js`
- تنسيق الإدارة الأساسي: `admin/styles.css`
- لا تُضاف طبقات CSS/JS جديدة لتجاوز خلل في الملف الأساسي إلا مؤقتًا وعلى فرع اختبار فقط.

## سياسة الحذف
يُحذف الملف فقط إذا تحقق شرطان معًا:
1. لا توجد أي إحالة إليه من HTML/JS/Python/Workflow أو مسار تشغيل.
2. توجد نسخة بديلة معتمدة أو ثبت أنه تاريخي/مكرر وغير مطلوب.

## خطة التنفيذ
### المرحلة A — بدون مخاطرة
- جرد جميع الملفات والـ workflows.
- اكتشاف الأسماء المكررة والملفات ذات المحتوى المتطابق.
- إعداد قائمة مرشحين للحذف دون حذف فعلي.
- تثبيت قائمة نقاط الدخول الفعلية.

### المرحلة B — تنظيف فرع الصيانة فقط
- نقل/حذف ملفات التعليمات التاريخية المكررة.
- تعطيل أو حذف workflows القديمة التي انتهت مهمتها بعد إثبات عدم الحاجة.
- عدم لمس `server.py` أو `admin/app.js` أو البيانات في هذه المرحلة.

### المرحلة C — اختبار كامل
- الإدارة، المستودع، السجل، الصور، الأزرار، التفعيلات، الصلاحيات، مسؤول إدخال البيانات، السوق، المزاد، البث، الطلبات والشحن.
- لا دمج إلى `main` إلا إذا اجتاز الاختبار كاملًا.

## قرار معماري ثابت
أي وظيفة إنتاجية يجب أن يكون لها مصدر واحد فقط. لا نكرر نفس منطق السجل أو المستودع أو الشحن في ملفات Patch متعددة.
